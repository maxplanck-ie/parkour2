restats report: what Parkour stores vs what the new parser reads

How to read this

Each row of the sqlite is one (library or lane, field). It is compared with the value Parkour stores now. ZERO = Parkour stores 0, the files say otherwise (old parser bug). WRONG = Parkour stores a non-zero value that differs (minor <1 %, moderate 1-10 %, major ≥10 %). MISSING = the API has this field but nothing is stored. NEW = a field Parkour does not expose yet (fragment_*, peak_*, ...). NOENTRY = no entry for that flowcell/barcode on this deployment. MATCH = nothing to fix.
