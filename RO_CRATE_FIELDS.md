# RO-Crate Fields

This file documents the RO-Crate payload generated by `GET /api/generate_ro_crate/`.

It is based on the current implementation in:

- `backend/library/ro_crate.py`
- `backend/library/models.py`
- `backend/sample/models.py`
- `backend/request/models.py`
- `backend/common/models.py`
- `backend/library_sample_shared/models.py`
- `backend/pooling/models.py`
- `backend/library_preparation/models.py`
- `backend/index_generator/models.py`
- `backend/flowcell/models.py`

## Important rules

- The JSON response is JSON-LD with top-level keys `@context` and `@graph`.
- Many values are emitted as `additionalProperty` entries of the form:

```json
{
  "@type": "PropertyValue",
  "name": "field_name",
  "value": "field_value"
}
```

- Empty values are skipped.
- Fields starting with `removed_` are skipped.
- Fields named `archived` are skipped.
- Some linked references are also stored inside `additionalProperty` with values like `{ "@id": "#some-entity" }`.
- The exact set of graph entities depends on the selected requests, samples, libraries, pools, flowcells, lanes, and linked metadata.

## Minimal no-match crate

If no requested barcodes or request names are found, the crate contains only:

### Metadata entity

- `@id`
- `@type`
- `conformsTo`
- `about`

### Dataset entity

- `@id`
- `@type`
- `name`
- `dateCreated`
- `description`
